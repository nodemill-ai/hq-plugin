# 미팅

원본 = 회사 Google **공유 드라이브**. 미팅 1건 = 폴더 1개 — hq 는 읽기 전용 창 (`https://hq.nodemill.ai/meetings`) 이고, 폴더 · 파일 **쓰기는 Google Drive 커넥터** (사용자 본인 권한) 가 한다. hq 에 미팅을 만드는 도구는 없다.

## 사내 · 사외

- **사외 (고객사 미팅) = 실제로 외부 고객과 만난 미팅만** → `고객사/<회사>/미팅/`. 참석자에 고객사 사람이 있으면 사외.
- **고객 일에 대해 우리끼리 한 미팅은 사내** → `운영/미팅/` 아래 (그 고객 일의 주제 폴더). 주제가 고객 일이어도 고객사 폴더에 두지 않는다 — 고객과의 미팅과 헷갈린다.

## 자리 규칙

미팅 1건 = 이름이 `YYYY-MM-DD_주제` 인 폴더 1개. hq 는 미팅 위치 (`운영/미팅` · `고객사/<회사>/미팅`) 아래에서 **이름이 날짜로 시작하는 폴더를 미팅으로, 그 위 폴더는 전부 묶음 (주제 · 연 · 월) 으로** 읽는다 — 날짜 없는 폴더 · 미팅 위치 바로 아래 파일은 미팅으로 안 보인다.

| 종류 | 자리 | 예 |
|---|---|---|
| 주간 미팅 (사내) | `운영/미팅/주간-미팅/YYYY-MM/YYYY-MM-DD_주간-미팅/` | `운영/미팅/주간-미팅/2026-11/2026-11-18_주간-미팅/` |
| 주제가 있는 사내 미팅 | `운영/미팅/<주제>/YYYY-MM-DD_<제목>/` | `운영/미팅/케이녹스-홈페이지-개발/2026-11-18_홈페이지-초기-스펙-논의/` |
| 그 밖의 사내 미팅 | `운영/미팅/YYYY/MM/YYYY-MM-DD_<제목>/` | `운영/미팅/2026/11/2026-11-03_hq-로드맵/` |
| 사외 | `고객사/<회사>/미팅/YYYY/MM/YYYY-MM-DD_<제목>/` | `고객사/광일금속/미팅/2026/11/2026-11-03_ERP-1차-시연/` |

- **주간 미팅** = 묻지 않고 `주간-미팅/YYYY-MM/` 아래 (`YYYY-MM` = 미팅 날짜의 연-월).
- **주제** (사내 · 주간 아님): 새 미팅 노트를 만들 때 한 번 정한다 — `listMeetings` 의 `topics` (이미 있는 주제 폴더) 를 먼저 보여 주고 고르거나 새로 만든다 (띄어쓰기만 다른 같은 주제는 기존 폴더). 사용자가 주제 없이 가자고 하면 `YYYY/MM/`. 주제 = 고객 일 · 프로젝트 같은 묶음 이름 (예 `케이녹스-홈페이지-개발`) — 에픽과 묶지 않는다.
- **묶음 폴더** (주제 · `주간-미팅` · 연 `YYYY` · 월 `MM` · `YYYY-MM`) 가 없으면 커넥터로 만든다 (규칙 고정 경로 — 승인 없이 · 새 주제 이름은 위에서 정한 것). 예전 미팅은 `미팅/` 바로 아래 · 옛 `YYYY/MM/` 에 있어도 hq 가 그대로 읽는다 — 옮기지 않는다. 옮기고 싶다고 하면 **Drive 앱에서 사용자가 끌어 옮기도록** 안내한다 (커넥터 `update_file` 의 부모 변경은 공유 드라이브에서 권한 거부 — 2026-11-04 실측 · 폴더 id 가 그대로라 태스크 연결은 유지된다).
- 폴더 이름 = 낱말을 `-` 로 잇는다 (공백 없음 · 주제 폴더도). 같은 날 같은 주제가 이미 있으면 `_2`.
- 회의록 frontmatter `title` = **`YYYY-MM-DD 주제 (공백)`** (예 `2026-11-04 주간 미팅`) — hq 목록 · 상세도 이 표기로 보인다.
- **같은 날 회사 캘린더 일정이 있으면 주제 = 그 일정 제목** (공백 → `-` · `listEvents { from: 그날, to: 그날 }`) — hq 캘린더가 일정 ↔ 회의록을 자동으로 묶는다. 사외는 일정 제목 앞의 고객사 이름을 빼고 (위치가 회사) 나머지를 주제로.
- 폴더 안: **`회의록.md`** (이름 고정 · 0~1개) + 자료 (슬라이드 · pdf · 이미지 — 이름은 `file` 스킬 규칙 `YYYYMMDD_주제_버전.확장자`, 사용자가 준 이름이 있으면 그대로).
- 종류 · 회사는 위치로 정해진다 — frontmatter 에 넣지 않는다.

### 사내 미팅 (노드밀)

- **주간 미팅** = 매주 수 17:00 반복 일정 `주간 미팅` → `운영/미팅/주간-미팅/YYYY-MM/YYYY-MM-DD_주간-미팅` · `tags: [미팅, 주간]`. **주제 미팅** = 필요할 때 · 폴더 제목 = 일정 제목 · 자리 = 주제 폴더 (자리 규칙) · `tags: [미팅]`.
- 템플릿 = `references/사내-회의록.md` 의 **"템플릿" 블록만** (사외는 `references/회의록.md`) — 그 파일 "쓰는 규칙" 의 설명 · 안내 문구는 노트에 넣지 않는다. 같은 `회의록.md` 하나가 미팅 전에는 안건 노트 (`status: 준비`), 정리 뒤에는 회의록 (`status: 완료`).
- 모양 = `---` 로 나눈 절 · **안건 하나 = `## N. 제목` 블록 하나** (`**기안**` · `**자료**` → `**상세**` → `**논의**` → `**결정**` → `**액션**` 표) · 맨 위 `## 안건` 표는 `# · 안건 · 기안` 만 (안건 칸 = 블록 앵커 링크) · 안건 밖 내용 = `## 기타` 블록. 이름 = 전체 이름 (`listMembers`) · 자료 = 전부 절대 URL 링크 (hq 태스크 · 로드맵 · 위키 · 가이드 · Drive · 외부 — 규칙 · 앵커 계산은 그 파일).
- 녹음 = CLOVA Note (오프라인 · 온라인 모두 폰 앱 — 온라인은 노트북 스피커 소리). 정리 입력 = CLOVA **요약** 텍스트 붙여넣기 · 다운로드 파일. 변환 = `references/clova-변환.md`.

## 사내 미팅 준비 — "주간 미팅 준비" · "안건 추가해 — …" · "<날짜> <주제> 미팅 노트 만들어"

1. **일정**: `listEvents` 에서 그 미팅 — 주간 = `{ from: 오늘, to: 오늘+7 }` 의 제목 `주간 미팅` 중 아직 끝나지 않은 첫 것 · 주제 = 말한 날짜 하루. 없으면 만들지 않고 "회사 캘린더에 일정부터 잡을까요?" (`schedule` 스킬). `UNAVAILABLE` 이면 일정 확인 없이 사용자가 말한 날짜 · 주제로 진행 (일정을 만들자고 하지 않는다). 폴더 제목 = 일정 제목 (공백 → `-`). **종일 일정 (`allDay`) 이고 노트가 아직 없으면 만들지 않고 "세부 일정 (시각) 을 먼저 정해 주세요"** (`schedule` 스킬로 시각을 넣을지 묻는다) — 이미 노트가 있으면 2번대로 덧붙인다.
2. **노트 찾기**: 일정의 `meeting` 이 있으면 그 폴더 · 없으면 `listMeetings { kind: "internal", from: 그날, to: 그날 }` 에서 같은 주제.
   - 있으면 `getMeeting` 으로 지금 `회의록.md` 를 읽고 **`## 안건` 표에 행 + `## 기타` 앞에 그 안건 블록을 덧붙인다** (번호 = 마지막 + 1 · 다른 사람이 쓴 행 · 블록을 지우거나 고치지 않는다) → 새 `회의록.md` 로 올리고 옛 파일은 `회의록_준비.md` 로 rename (§ 규칙).
   - 없으면 자리 규칙대로 폴더 (부모 = 주간 → `주간-미팅/YYYY-MM` · 그 밖 → 주제 폴더 또는 `YYYY/MM` — 주제는 자리 규칙대로 한 번 묻는다 · 정리 5-1) + `회의록.md` (`status: 준비` · 머리 3줄 · 지난 액션 · 안건 표 · 안건 블록 (논의 · 결정 · 액션 빈 틀) · 기타 빈 틀 · 다음 미팅으로 넘김 · 자료) 를 만든다 (정리 5번과 같은 옵션).
3. **안건 1개** = 표 1행 `| N | [제목](#<앵커>) | <기안> |` + 블록 1개. 기안 = 말한 사람 전체 이름 (모르면 묻는다). 말에 담긴 배경 · 선택지 · 일정은 `**상세**` 불릿 (결정이 필요하면 선택지 A / B 까지 — 목적은 묻지 않는다) · 언급된 태스크 키 · 로드맵 · 위키 · URL 은 `**자료**` 링크 (`getTaskByKey` · `listRoadmaps` · `getWikiPage` 로 확인한 것만 — 못 찾으면 이름만). 상세가 없으면 `-`.
4. **지난 액션 (주간 · 주제 미팅 · 노트를 처음 만들 때만 — 덧붙이기 때는 `## 지난 액션` 을 건드리지 않는다 · 정리 7번만 예외)**: 직전 미팅 = 주간이면 `listMeetings { kind: "internal", q: "주간 미팅", to: 어제 }` 에서 `topic` 이 `주간-미팅` 인 첫 행 (`주간-미팅/` 묶음이든 옛 `YYYY/MM/` 자리든) · 주제 미팅이면 `listMeetings { kind: "internal", to: 어제 }` 에서 `group` 이 같은 주제인 첫 행 → `getMeeting`. 연 · 월 자리 (주제 없음) 미팅은 `없음` 1행.
   - `tasks` (`key · title · status`) 중 **done 이 아닌 것** = `## 지난 액션` 표 (키 칸 = 키 링크 · 상태 원본 = hq 연결 · 정리 6번이 미완료 액션을 매주 이월 연결한다). 담당 · 마감은 그 회의록의 안건 · 기타 블록 액션 표 · `## 지난 액션` 표에서 (옛 구조 회의록이면 "5. 액션 아이템" · "1." 표), 없으면 `getTaskByKey` (`assigneeId` → `listMembers` 이름).
   - 지난 회의록 `## 다음 미팅으로 넘김` (옛 구조 "6.") 항목은 이번 안건으로 덧붙인다 — 제목 끝에 ` (넘어옴)` · 기안 = 지난 블록의 기안 (없으면 `—`) · 상세 첫 불릿 = `지난 미팅 [YYYY-MM-DD 주제](<hqUrl>) 에서 넘어옴 — <이유>` (이미 있는 안건이면 다시 넣지 않는다). 첫 주간 미팅이면 `없음 (첫 미팅)` 1행.
5. **보고**: 폴더 · hq 링크 (`hqUrl`) · 안건 수 · 미완료 지난 액션 수 · "미팅 뒤 CLOVA 요약을 붙여 '주간 미팅 정리해 줘' 하세요".

## 정리 · 올리기 — "미팅 정리해 줘" (+ 메모 · 녹취 텍스트 · 슬라이드)

1. **자리 판정**: 사내 / 사외를 참석자 · 말에서 정한다 (§ 사내 · 사외 — 외부 고객이 참석했으면 사외 · 고객 일이라도 우리끼리면 사내). 애매하면 묻는다. 사내면 주간 / 주제 / 연월 (자리 규칙 · 주제는 `topics` 먼저).
   - 사외: `listMeetings { kind: "external" }` 의 `companies` 에서 회사를 고른다.
     - `meetingsFolderId` 가 있으면 그 폴더가 부모.
     - 회사는 있는데 `meetingsFolderId` 가 null 이면 → 커넥터로 `고객사/<회사>/미팅` 폴더를 만든다 (규칙 고정 경로 — 승인 없이).
     - 회사가 없으면 → "`고객사/<회사>` 를 새로 만들까요?" 로 제안 · 승인 (`file` 스킬 규칙 — 승인 없이 회사 폴더를 만들지 않는다).
   - 노드밀: `listMeetings { kind: "internal" }` 결과가 비어 있어도 된다. `운영/미팅` 폴더 id 는 `searchDrive { q: "미팅" }` 의 `path` 가 `운영` 인 폴더 — 없으면 `운영` 아래에 커넥터로 `미팅` 을 만든다 (규칙 고정 경로 — 승인 없이 · 루트에는 만들지 않는다).
2. **회의록 작성**:
   - 사외: `references/회의록.md` 템플릿 목차대로 — frontmatter (`title` · `date` · `attendees` · `tags`) · **일시 · 참석** · **안건** · **논의** · **결정 사항** · **후속 태스크** · **자료**.
   - 사내: 그날 (말한 날) 같은 주제의 `status: 준비` 노트가 있으면 (`listMeetings { kind: "internal", from, to }` → `getMeeting`) **그 파일을 채운다** — 머리 · 안건 표 · 블록의 기안 · 자료 · 상세는 남기고 `references/clova-변환.md` 대로 각 블록의 논의 · 결정 · 액션 · `## 기타` 블록 · `## 다음 미팅으로 넘김` · `## 지난 액션` 상태 · 피드백을 채운 뒤 `status: 완료`. 노트가 없으면 `references/사내-회의록.md` 템플릿 블록으로 새로 (주제 = 그날 `listEvents` 일정 제목 · 안건 = 요약의 '주요 주제' · 지난 액션은 준비 4번처럼).
   - 메모 · 요약에 없는 내용은 지어내지 않는다 (빈 칸은 "없음" · 담당 = `확인 필요` — 사내 회의록의 액션 밖 칸은 `—` (`clova-변환.md` § 4)). 날짜는 한국 시간 `YYYY-MM-DD`.
3. **후속 태스크 후보**: 결정 사항 · 할 일에서 뽑는다 (담당 · 마감 포함). `task` 스킬 규칙대로 사일로 · 담당 id 를 조회해 둔다 (아직 만들지 않는다).
   - 사내: **안건마다 액션 ≥ 1** — 없으면 `액션 없음 — <이유>` (공유 안건은 `액션 없음 — 공유`). 지난 액션은 `종료 → done` / `기존 갱신` / 그대로 (`clova-변환.md` § 3).
4. **한 줄 확인**: (사내는 "새 태스크 N · 갱신 M · 종료 K · 마감 미정 L 건 (담당이 정함) · 확인 필요 J 행" + 새 태스크마다 사일로 추천 (`listSilos` · `task` 스킬 규칙) 을 함께 — 마감은 묻지 않고 `확인 필요` (담당 · 사일로) 만 여기서 한 번에 묻는다 · 답 전에는 아무것도 쓰지 않는다) "`고객사/광일금속/미팅/2026/11/2026-11-03_ERP-1차-시연/` 에 회의록 + 자료 2개 · 후속 태스크 3개 (① … ② … ③ …) — 올릴까요?" — 사용자가 빼거나 고친 것을 반영한다. 사내 주간 미팅이면 7번의 일정을 먼저 찾아 같은 줄에 "· 다음 주간 미팅 (YYYY-MM-DD) 준비 노트도 만듦" 을 덧붙여 한 번에 승인받는다 (일정이 없으면 "· 다음 주간 미팅 일정 없음 — 준비 노트 안 만듦").
5. **올리기** (Google Drive 커넥터 `create_file` · 준비 노트가 있으면 그 파일 (`minutes.fileId`) 은 `update_file { fileId, title: "회의록_준비.md" }` 로 이름만 바꾼다 · 삭제 안 함). 사내 순서 = (폴더가 없으면 폴더 생성) → 6 의 hq 반영 → 키를 채운 회의록을 **한 번** 쓴다 (기존 파일이면 쓰기 직전 `getMeeting` 으로 다시 읽어 합침 · 키 자리표시 없이):
   1. 미팅 폴더 생성 — 부모 = 1 의 미팅 폴더 (`운영/미팅` · `고객사/<회사>/미팅`) 아래 자리 규칙의 묶음: 주간 = `주간-미팅` → `YYYY-MM` · 주제 = `<주제>` · 그 밖 사내 · 사외 = `YYYY` → `MM` (미팅 날짜). `listDriveFolder { folderId: <미팅 폴더 id> }` 부터 한 단씩 찾고, 없으면 커넥터로 만든다 (승인 없이 · 주제 이름은 1번에서 정한 것).
   2. `회의록.md` — `create_file { parentId: 미팅 폴더, title: "회의록.md", textContent` = 회의록 전문 · `contentMimeType: "text/markdown"` · **`disableConversionToGoogleType: true`** (안 그러면 Google 문서로 바뀌어 hq 가 본문을 못 그린다).
   3. 자료 — `base64Content` + `contentMimeType` (같은 옵션). 첨부 바이트를 넘길 수 없으면 회의록만 올리고 "자료는 Drive 앱 · hq 파일 화면에서 이 폴더로 올려 주세요" 로 폴더 링크를 준다.
6. **후속 태스크**: 확인받은 항목마다 `createTask` (사외 미팅이면 `customer` = 그 미팅의 회사 이름 — `listMeetings` 의 `company` 그대로) → `linkResource { taskId, kind: "meeting", ref: <미팅 폴더 id>, title: "<YYYY-MM-DD> <주제 (공백)>" }` → 만든 키를 회의록 "후속 태스크" 절 (사내 = 그 안건 · 기타 블록 액션 표의 키 칸 · 링크 `[HQ-0000](https://hq.nodemill.ai/tasks?task=HQ-0000)`) 에 채워 5 의 `회의록.md` 에 한 번에 담는다.
   - 사내 갱신: `getTaskByKey` (id) → `changeTaskStatus` · 마감 · 담당이 바뀌었으면 `updateTask` → 이 미팅에도 `linkResource` (같은 형식).
   - 사내 종료: `getTaskByKey` → `changeTaskStatus { taskId, status: "done" }` → `addComment { taskId, body: "<YYYY-MM-DD> <주제 (공백)> 에서 종료 — <근거 한 줄>" }` → 이 미팅에도 `linkResource` (미팅 화면에서 종료가 보이게).
   - 사내 이월: `## 지난 액션` 에서 언급 없이 미완료로 남은 키도 전부 이 미팅에 `linkResource` — 안 그러면 다음 주 준비 (4번) 에서 빠진다.
   - 사내 마감 미정: `dueDate` 없이 `duePending: true` 로 만든다 (담당의 브리핑 "확인 요청" 에 "마감 정하기" 로 뜬다 · 담당이 `dueDate` 를 넣으면 풀린다).
   - 사내 "각자 · 모두": 참석자마다 1개 (`<할 일> — <이름>`) · 전부 이 미팅에 `linkResource`.
   - 담당이 정해지지 않은 행은 만들지 않는다 (키 칸 `(담당 정해지면)`).
7. **다음 주간 미팅 준비 노트** (사내 주간 미팅만 · 4번에서 승인받았으니 다시 묻지 않는다): 5 · 6 이 끝난 뒤 § 사내 미팅 준비 1 · 2 · 4 번 절차로 다음 주간 미팅의 `status: 준비` 노트를 만든다. 다른 점만:
   - 일정 = `listEvents { from: 내일, to: 오늘+8 }` 의 제목 `주간 미팅` 첫 것. 없으면 만들지 않는다 ("일정부터 잡을까요" 도 묻지 않는다 — 8번 보고에 한 줄). `UNAVAILABLE` 이면 이번 미팅 날짜 + 7일로 만든다 (그 날짜가 이미 지났으면 만들지 않는다).
   - 지난 미팅 = 준비 4번의 검색 대신 **방금 정리한 이 미팅** (`getMeeting { meetingId: <이 폴더 id> }` — 당일 정리한 미팅은 `to: 어제` 에 안 잡힌다). 그 `tasks` 중 done 이 아닌 것 = `## 지난 액션` 표 · 그 회의록의 `## 다음 미팅으로 넘김` = ` (넘어옴)` 안건.
   - 그 날짜 노트가 이미 있으면 (누가 미리 안건을 넣은 것 — 한 주 전 미팅 기준으로 만들어졌다) 안건 행 · 블록은 그대로 두고, 넘어온 안건만 덧붙이고 (준비 2번 · 이미 있으면 다시 넣지 않는다) `## 지난 액션` 표를 이 미팅 기준으로 바꾼다.
8. **확인 · 보고**: `getMeeting { meetingId: <폴더 id> }` 로 회의록 (`minutes.status: ok`) · 자료가 보이는지 확인 → 미팅 제목 · 자리 · hq 링크 (`hqUrl` = `https://hq.nodemill.ai/meetings?m=<id>`) · 만든 태스크 키를 보고. 목록 화면에는 최대 5분 늦게 보일 수 있다 (링크는 바로 열린다). 7번을 했으면 다음 노트의 날짜 · hq 링크 · 넘어간 안건 수 · 미완료 지난 액션 수 · "안건은 '안건 추가해 — …' 로 미리 넣으세요" 를 더하고, 안 만들었으면 "다음 주간 미팅 일정이 캘린더에 없어 준비 노트를 만들지 않았어요" 한 줄.

## 찾기 · 회상 — "지난 광일 미팅 뭐였지" · "ERP 시연 때 뭐 정했지"

1. `listMeetings` — 회사면 `company`, 주제 · 내용이면 `q` (제목 부분 일치 + 회의록 · 자료 내용의 낱말 일치), 기간이면 `from` / `to`. `contentSearched: false` 면 내용 검색이 안 된 것 — 다른 낱말로 한 번 더.
2. 고른 미팅을 `getMeeting` → 결정 사항 · 후속 태스크 (`tasks` 의 키 · 상태) 를 요약하고 `hqUrl` 링크.
3. 주간 미팅이면 지난 몇 주 회의록의 `## 지난 액션` (옛 구조 "1. 지난 액션 확인") 에서 같은 키가 연속으로 미완료인 것을 한 줄로 ("HQ-0123 3주째 doing").
4. 회의록이 없는 미팅 (`minutes: null`) 은 자료 이름 · 링크를 준다. `minutes.status: unreadable` 이면 Drive 에서 열라고 안내.

## 덧붙이기 — "이 슬라이드 어제 광일 미팅에 넣어"

1. `listMeetings { company, from }` 로 미팅을 찾는다 (여럿이면 고르게 한다).
2. 파일 이름 · 미팅을 한 줄로 확인 → 커넥터로 그 미팅 폴더 (`id`) 에 업로드 (`disableConversionToGoogleType: true`).
3. 회의록이 있으면 "자료" 절에 파일 이름을 더할지 묻는다 (`getMeeting` 의 `minutes.fileId` → 새 `회의록.md` 로 올리고 옛 파일 rename · § 규칙).

## 규칙

- 커넥터 `update_file` 은 내용을 못 바꾼다 (메타데이터만) — 내용 변경은 항상 새 파일 + 옛 파일 rename (옛 것은 `회의록_준비.md` · 이미 있으면 `회의록_준비2.md`). 미팅 중 · 준비 노트를 다시 고칠 때도 같다.
- 회의록 고치기는 `getMeeting` 으로 지금 내용을 읽은 뒤 합쳐서 — 다른 사람이 Drive 에서 고친 내용을 덮어쓰지 않는다.
- 위키 회의록 템플릿 (`_templates/회의록.md`) · 위키 문서로 미팅을 쓰지 않는다 — 미팅은 이 스킬 (공유 드라이브).
- 미팅 위치 밖 폴더 · 이름이 날짜로 시작하지 않는 폴더 · 묶음 4단보다 깊은 폴더 id 는 hq 에서 `NOT_FOUND` — 자리 규칙대로 옮기자고 (또는 폴더 이름 앞에 날짜를) 안내한다 (이동은 사용자가 Drive 앱에서 — 커넥터로는 못 옮긴다 · 다시 만들고 지우는 우회는 폴더 id 가 바뀌어 태스크 연결이 끊기므로 하지 않는다).
- 비밀번호 · 키 · 개인정보가 든 메모는 올리기 전에 한 번 확인한다.
- CLOVA Note 는 연동 API 가 없다 — 녹음 · 요약은 사용자가 CLOVA 에서 하고 텍스트를 준다. 영상 파일은 CLOVA 에 못 올린다 (음성 m4a · mp3 · aac · amr · wav).
- `UNAVAILABLE` 이면 Drive 한도 · 장애 — 잠시 뒤 다시. 401 · 연결 오류면 "hq 연결이 끊겼다 — Claude Code 는 `/mcp` 에서, claude.ai 는 플러그인 Connectors 탭에서 hq 에 다시 로그인" 을 안내하고 멈춘다.
