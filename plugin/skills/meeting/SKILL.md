# 미팅

원본 = 회사 Google **공유 드라이브**. 미팅 1건 = 폴더 1개 · 안의 **`회의록.md`** 하나가 미팅 전 = 안건 노트 (`status: 준비`) · 정리 뒤 = 회의록 (`status: 완료`). **`회의록.md` 쓰기는 전부 hq 도구** — `prepareMeeting` (노트 준비: 있으면 그대로 · 없으면 자리 폴더 + 양식 뼈대를 만든다) · `addMeetingAgenda` (안건 1개 덧붙이기 — 노트가 없으면 만들고 넣는다) · `writeMeetingMinutes` (본문 전체 쓰기 — 지난 액션 · 넘어온 안건 채우기 · 정리). hq 미팅 화면 (`https://hq.nodemill.ai/meetings`) 의 "안건 추가" 와 같은 함수라 웹 · Claude 가 같은 노트에 쌓는다. **자료 파일 (슬라이드 · pdf · 이미지) 올리기만 Google Drive 커넥터** (사용자 본인 권한).

## 사내 · 사외

- **사외 (고객사 미팅) = 실제로 외부 고객과 만난 미팅만** → `고객사/<회사>/미팅/`. 참석자에 고객사 사람이 있으면 사외.
- **고객 일에 대해 우리끼리 한 미팅은 사내** → `운영/미팅/` 아래 (그 고객 일의 주제 폴더). 주제가 고객 일이어도 고객사 폴더에 두지 않는다 — 고객과의 미팅과 헷갈린다.

## 자리 규칙

hq 는 미팅 위치 (`운영/미팅` · `고객사/<회사>/미팅`) 아래에서 **이름이 날짜 `YYYY-MM-DD` 로 시작하는 폴더를 미팅으로** (날짜 뒤는 `_` · `-` · 공백 아무거나 — `2026-11-18 주간 미팅` = `2026-11-18_주간-미팅`), **그 위 폴더는 전부 묶음 (주제 · 연 · 월)** 으로 읽는다 — 날짜 없는 폴더 · 미팅 위치 바로 아래 파일은 미팅이 아니다. 새 노트의 폴더는 hq 도구가 이 자리에 만든다 (커넥터로 폴더를 만들지 않는다).

| 종류 | 자리 | 예 |
|---|---|---|
| 주간 미팅 (사내) | `운영/미팅/주간-미팅/YYYY-MM/YYYY-MM-DD_주간-미팅/` | `운영/미팅/주간-미팅/2026-11/2026-11-18_주간-미팅/` |
| 주제가 있는 사내 미팅 | `운영/미팅/<주제>/YYYY-MM-DD_<제목>/` | `운영/미팅/다라상사-홈페이지-개발/2026-11-18_홈페이지-초기-스펙-논의/` |
| 그 밖의 사내 미팅 | `운영/미팅/YYYY/MM/YYYY-MM-DD_<제목>/` | `운영/미팅/2026/11/2026-11-03_hq-로드맵/` |
| 사외 | `고객사/<회사>/미팅/YYYY/MM/YYYY-MM-DD_<제목>/` | `고객사/가나금속/미팅/2026/11/2026-11-03_ERP-1차-시연/` |

- **주간 미팅** (일정 제목 `주간 미팅`) = hq 가 묻지 않고 `주간-미팅/YYYY-MM/` 아래 · `tags: [미팅, 주간]`.
- **자리 묻기**: 노트를 새로 만들 때 hq 가 INVALID `place-required` 를 돌려주면 그때만 묻는다 — `details.topics` (이미 있는 주제 폴더) · `details.customers` (hq 고객사) 와 위 사내 · 사외 정의를 보여 주고 사내 (기본) + 주제 (선택 — 있는 이름을 먼저 재사용 · 띄어쓰기만 다른 같은 주제는 hq 가 기존 폴더로) / 고객사 를 고르게 한 뒤 같은 호출에 `place` · `topic` / `company` 를 더해 다시. 주제 = 고객 일 · 프로젝트 같은 묶음 이름 — 에픽과 묶지 않는다. 고객사는 hq 고객사만 (`unknown-company` = 태스크의 고객사 칸으로 먼저 만들어야 한다고 안내) · 그 회사 폴더가 Drive 에 없으면 hq 가 만든다.
- 회의록 제목 = `YYYY-MM-DD <일정 제목>` (예 `2026-11-04 주간 미팅`) — hq 가 정한다. 같은 날 같은 제목의 일정은 노트 하나로 묶인다.
- 예전 미팅은 `미팅/` 바로 아래 · 옛 `YYYY/MM/` 에 있어도 hq 가 그대로 읽는다 — 옮기지 않는다. 옮기고 싶다고 하면 **Drive 앱에서 사용자가 끌어 옮기도록** 안내한다 (커넥터의 부모 변경은 공유 드라이브에서 권한 거부 · 폴더 id 가 그대로라 태스크 연결은 유지된다).
- 폴더 안: `회의록.md` (0~1개) + 자료 (이름은 `file` 스킬 규칙 `YYYYMMDD_주제_버전.확장자`, 사용자가 준 이름이 있으면 그대로). 종류 · 회사는 위치로 정해진다 — frontmatter 에 넣지 않는다.

## 양식 · 쓰는 규칙

- **양식 원본 = 위키 `_templates/회의록-사내.md` · `_templates/회의록-사외.md`** — hq 가 새 노트에 자동으로 쓴다. 모양을 봐야 할 때 (노트 없이 정리할 때 · 블록을 손으로 쓸 때) `getWikiPage { path: "_templates/회의록-사내.md" }` 로 읽는다. 양식의 HTML 주석 (칸별 설명) · `{{…}}` 자리표시 · `{{번호}}` 견본 줄은 노트에 넣지 않는다 — 뼈대만.
- 사내 노트를 쓰는 규칙 (구분선 · 머리 3줄 · 안건 표 · 앵커 · 이름 · 링크 · 준비 / 정리 뒤 칸) = `references/사내-회의록.md`. CLOVA 요약 → 논의 · 결정 · 액션 = `references/clova-변환.md`.
- 녹음 = CLOVA Note (오프라인 · 온라인 모두 폰 앱 — 온라인은 노트북 스피커 소리). 정리 입력 = CLOVA **요약** 텍스트 붙여넣기 · 다운로드 파일.

## 안건 추가 — "11/25 주간 미팅에 안건 추가해 — …" · "<날짜> <주제> 미팅 노트 만들어"

1. **대상**: `listEvents` 에서 그 미팅 일정 — 주간 = `{ from: 오늘, to: 오늘+7 }` 의 제목 `주간 미팅` 중 끝나지 않은 첫 것 (날짜를 말했으면 그날) · 주제 = 말한 날짜 하루. 대상 = `eventId` (일정의 `meeting` 이 있으면 `meetingId` 도 된다). 일정이 없으면 "회사 캘린더에 일정부터 잡을까요?" (`schedule` 스킬) — 일정 없이 가자고 하거나 `listEvents` 가 `UNAVAILABLE` 이면 `date` + `meetingTitle`.
2. **안건**: `title` · `proposerId` (기안 = 말한 사람 — `listMembers` 의 id · 생략 = 나) · `detail` (말에 담긴 배경 · 현재 상태 · 결정이 필요하면 선택지 A / B — 줄마다 한 항목 · 목적은 묻지 않는다) · `links` (언급된 태스크 키 `HQ-0057` · 로드맵 · 위키 · URL — `getTaskByKey` · `listRoadmaps` · `getWikiPage` 로 확인한 것만 · 로드맵 · 위키는 `hqUrl` · 못 찾으면 상세에 이름만).
3. `addMeetingAgenda { eventId | meetingId | date + meetingTitle, agenda }` — 노트가 있으면 다음 번호로 덧붙이고 (다른 사람이 쓴 행 · 블록 · 내용은 hq 가 그대로 둔다) 없으면 만들고 넣는다. `place-required` 면 § 자리 규칙대로 묻고 다시.
4. `needsFill: true` (사내 노트를 방금 만들었다) 면 이어서 § 준비 3 ~ 5 로 지난 액션 · 넘어온 안건을 채운다.
5. **보고**: 미팅 제목 · 안건 번호 · hq 링크 (`https://hq.nodemill.ai/meetings?m=<meetingId>`) · (만들었으면) 자리.

## 준비 — "주간 미팅 준비해 줘" · "<주제> 미팅 준비해 줘"

1. **대상**: § 안건 추가 1 과 같다.
2. `prepareMeeting { eventId | meetingId | date + meetingTitle }` → 노트 (있으면 그대로 · 없으면 만든다 — `place-required` 면 § 자리 규칙대로).
3. **직전 미팅**: 주간 = `listMeetings { kind: "internal", q: "주간 미팅", to: 이 미팅 전날 }` 에서 `group` 이 `주간-미팅` 인 첫 행 (옛 `YYYY/MM/` 자리의 주간 미팅은 `group` 이 없고 `topic` 이 `주간-미팅` · `주간 미팅`) · 주제 미팅 = `listMeetings { kind: "internal", to: 이 미팅 전날 }` 에서 `group` 이 같은 주제인 첫 행 → `getMeeting`. **직전 미팅 시작** = 그 회의록 `**일시**` 줄의 시작 시각 (한국 시간 · 시각이 없으면 그날 0시). 연 · 월 자리 (`group` 없음) 미팅 · 사외 미팅은 지난 액션을 채우지 않는다 (사내 연월 = 두 표 모두 `없음` 1행).
4. **채울 내용** (모양 · 묶음 · 순서 · 칸 = `references/사내-회의록.md` § 지난 액션) — `## 지난 액션` 은 두 절 · **hq 태스크만** (보류함으로 옮긴 · 지운 태스크는 조회 목록에 안 나온다 → 뺀다 · 다시 찾지 않는다):
   - **조회** (주간 — 한 번씩 부르고 그 결과로 고른다 · 묶음은 제목으로 짐작하지 않는다): `listTasks { completedFrom: <직전 미팅 날짜> }` (완료) · `listTasks { status: "todo" }` · `{ status: "doing" }` · `{ status: "review" }` (안 끝난 일 전부 — 에픽 · 담당 · 마감 · `duePending` · 상태가 함께 온다) · `listEpics { activeOnly: false }` · `listRoadmaps { activeOnly: false }` (에픽 → 로드맵 · 이름 · 계획 시작) · `listMembers` (담당 이름). 주제 미팅은 직전 미팅 `tasks` 키마다 `getTaskByKey` + `listEpics { activeOnly: false }` · `listRoadmaps { activeOnly: false }` · `listMembers` (주제 미팅은 몇 주씩 떨어져 목록이 커진다).
   - `### 완료` = **직전 미팅 시작 이후 끝낸 태스크** (`completedAt` 은 UTC — 한국 시간 = +9시간으로 비교). 주간 = 완료 목록에서 `completedAt` 이 직전 미팅 시작 이후인 것 전부 (구성원 전원 · 미팅 연결과 무관) · 주제 = 직전 미팅 `tasks` 중 `done` 인 키. **뺄 키**: 직전 회의록에 이미 done 으로 적힌 것 (그 회의록의 완료 표 행 · 진행 중 표 상태 `done` · 옛 회의록의 `## 지난 액션` 한 표 상태 `done` · 액션 표 구분 `종료 → done` · `(done)`) · 이 노트의 진행 중에 남는 것 (아래). 행 = 제목 (주간 미팅에서 직전 미팅 `tasks` 에 있던 키면 끝에 ` (지난 액션)`) · 담당 (`assigneeId` → `listMembers` 이름) · 완료일 (`completedAt` 의 한국 시간 날짜) · 키 링크. 맨 위 줄 `지난 미팅 (YYYY-MM-DD HH:MM) 이후 완료 N건 · YYYY-MM-DD HH:MM 기준` (기준 = 지금).
   - `### 진행 중 · 예정` = **안 끝난 태스크** — 주간 = 직전 미팅 `tasks` 중 done 이 아닌 것 + 연결과 무관하게 마감 (`dueDate`) 이 **이 미팅 날짜 + 6일 이하** (이미 지난 마감 포함 — 다음 주까지 끝낼 일) 인 것 + 연결 · 마감과 무관하게 상태가 `doing` · `review` 인 것 (지금 손대고 있는 일) (`duePending` 인 todo 는 연결된 것만) · 주제 = 직전 미팅 `tasks` 중 done 이 아닌 것. 담당 · 마감 · 상태 = 조회한 hq 값 (회의록 글자를 옮기지 않는다). 정리 6번이 이 절의 미완료 키를 매주 이 미팅에 연결해 이어 간다. 다시 부를 때 피드백이 적힌 행은 끝났어도 상태 `done` 으로 이 절에 남긴다 (값은 완료 목록의 같은 키).
   - **태스크가 없는 지난 액션** (직전 회의록 안건 · 기타 블록 액션 표에서 키 칸에 태스크 키 `HQ-…` 가 없는 행 — 할 일 칸이 빈 행 · `액션 없음 — …` 은 뺀다) = `## 기타` 의 `### 기타 1. 태스크가 없는 지난 액션` 블록 (`references/사내-회의록.md`) — 없으면 만들지 않는다.
   - 첫 미팅이면 두 절 모두 `없음 (첫 미팅)` 1행.
   - 넘어온 안건 = 직전 회의록 `## 다음 미팅으로 넘김` (옛 구조 "6.") 항목마다 안건 표 1행 + 블록 1개 (번호 = 마지막 + 1) — 제목 끝 ` (넘어옴)` · 기안 = 지난 블록의 기안 (없으면 `—`) · 상세 첫 불릿 = `지난 미팅 [YYYY-MM-DD 주제](<hqUrl>) 에서 넘어옴 — <이유>`. 이미 있는 안건이면 다시 넣지 않는다.
5. **쓰기**: `getMeeting { meetingId }` (이 미팅) 의 `minutes.content` (회의록.md 원문 그대로 · frontmatter 포함) 위에 4 를 합친다 — 다른 안건 · 내용 · frontmatter 는 한 글자도 바꾸지 않는다 → `writeMeetingMinutes { meetingId, content, baseModifiedTime: minutes.modifiedTime }` (`content` = 그 원문을 고친 것 — frontmatter 를 따로 다시 조립하지 않는다). **`stale` 이면 `getMeeting` 으로 다시 읽어 새 내용 위에 같은 변경을 다시 합쳐 다시 쓴다** (덮어쓰지 않는다 · 두 번째도 `stale` 이면 멈추고 알린다). **다시 부르면** (이미 채운 노트) `## 지난 액션` 절 (제목부터 다음 `---` 앞까지 — 절 안에는 `---` 가 없다) 만 4 로 새로 쓴다 — 진행 중 · 예정에 누가 쓴 피드백은 키로 찾아 (어느 묶음 표에 있든) 새로 쓴 그 행에 옮기고, 안건 · 다른 절은 그대로 (넘어온 안건 · 「태스크가 없는 지난 액션」 블록은 빠진 것만 넣고 이미 있는 것은 다시 넣지 않는다). `status: 완료` (정리된) 노트는 다시 채우지 않는다 — "이미 정리된 미팅이에요".
6. **보고**: 미팅 · hq 링크 · 안건 수 · 넘어온 안건 수 · 완료 N · 진행 중 · 예정 M · "미팅 날 한 번 더 '주간 미팅 준비' 하면 그사이 끝낸 일이 완료 표에 들어가요 · 미팅 뒤 CLOVA 요약을 붙여 '주간 미팅 정리해 줘' 하세요".

## 정리 — "회의록 정리해 줘" · "주간 미팅 정리해 줘" · "미팅 정리해 줘" (+ CLOVA 요약 · 메모 · 슬라이드)

1. **자리 판정**: 사내 / 사외를 참석자 · 말에서 정한다 (§ 사내 · 사외). 애매하면 묻는다. 그 미팅 = 그날 `listEvents` 일정 (`meeting` 이 있으면 그 노트) · 없으면 `listMeetings { kind, from: 그날, to: 그날 }` 의 같은 제목. 노트가 없으면 5번에서 `prepareMeeting` 으로 만든다 (일정이 있으면 `eventId` · 없으면 `date` + `meetingTitle` · 1번에서 정한 `place` · `topic` / `company` 를 함께 — 주제는 `listMeetings` 의 `topics` 를 먼저 보여 준다).
2. **회의록 작성** (아직 쓰지 않는다 — 4번 확인 뒤):
   - 사내 준비 노트가 있으면 (`getMeeting`) **그 내용을 채운다** — 머리 · 안건 표 · 블록의 기안 · 자료 · 상세는 남기고 `references/clova-변환.md` 대로 각 블록의 논의 · 결정 · 액션 · `## 기타` 블록 · `## 다음 미팅으로 넘김` · `## 지난 액션` (`### 완료` 는 § 준비 4 규칙으로 **이번 미팅 시작 시각까지** 다시 채움 — 기준 줄 = 이번 미팅 시작 · 일시 줄에 시각이 없으면 그날 24:00 · 진행 중 표에 있는 키는 넣지 않는다 / `### 진행 중 · 예정` 은 행 · 묶음을 그대로 두고 피드백 + 담당 · 마감 · 상태 — 언급 없는 행도 전부 hq 반영 뒤 값으로 다시 읽는다: 주간 = § 준비 4 의 세 `status` 목록 → 없으면 완료 다시 채우기에 쓴 완료 목록 (`done`) → 둘 다 없으면 보류함 · 삭제로 보고 그 행을 지운다 (이월 · 연결하지 않는다) / 주제 = 키마다 `getTaskByKey` (`NOT_FOUND` = 지운다) / `### 기타 1. 태스크가 없는 지난 액션` 은 `clova-변환.md` § 3) 을 채운 뒤 `status: 완료`. 노트가 없으면 위키 `_templates/회의록-사내.md` 의 뼈대로 (안건 = 요약의 '주요 주제' · 지난 액션은 § 준비 3 · 4 처럼).
   - 사외: 위키 `_templates/회의록-사외.md` 의 목차대로 — frontmatter (`title` · `date` · `attendees` · `tags` · `status: 완료`) · **일시 · 참석** · **안건** · **논의** · **결정 사항** · **후속 태스크** · **자료**.
   - 메모 · 요약에 없는 내용은 지어내지 않는다 (빈 칸은 "없음" · 담당 = `확인 필요` — 사내 회의록의 액션 밖 칸은 `—` (`clova-변환.md` § 4)). 날짜는 한국 시간 `YYYY-MM-DD`.
3. **후속 태스크 후보**: 결정 사항 · 할 일에서 뽑는다 (담당 · 마감 포함). `task` 스킬 규칙대로 사일로 · 담당 id 를 조회해 둔다 (아직 만들지 않는다).
   - 사내: **안건마다 액션 ≥ 1** — 없으면 `액션 없음 — <이유>` (공유 안건은 `액션 없음 — 공유`). 지난 액션은 `종료 → done` / `기존 갱신` / 그대로 (`clova-변환.md` § 3).
4. **한 줄 확인**: (사내는 "새 태스크 N · 갱신 M · 종료 K · 마감 미정 L 건 (담당이 정함) · 확인 필요 J 행" + 새 태스크마다 사일로 추천 (`listSilos` · `task` 스킬 규칙) 을 함께 — 마감은 묻지 않고 `확인 필요` (담당 · 사일로) 만 여기서 한 번에 묻는다 · 답 전에는 아무것도 쓰지 않는다) "`고객사/가나금속/미팅/2026/11/2026-11-03_ERP-1차-시연/` 에 회의록 + 자료 2개 · 후속 태스크 3개 (① … ② … ③ …) — 올릴까요?" — 사용자가 빼거나 고친 것을 반영한다. 6 의 후속 태스크 설명 · 종료 댓글은 이 승인에 포함한다 — `task` 스킬의 "쓴 글을 먼저 보이고 확인" 은 미팅 정리에서는 하지 않는다 (태스크마다 묻지 않는다). 대신 승인받은 회의록 (논의 · 결정 · 액션) 에 있는 내용으로만 쓰고, 회의록에 없는 이유 · 날짜 · 다음 계획을 덧붙이지 않는다. 사내 주간 미팅이면 7번의 일정을 먼저 찾아 같은 줄에 "· 다음 주간 미팅 (YYYY-MM-DD) 준비 노트도 만듦" 을 덧붙여 한 번에 승인받는다 (일정이 없으면 "· 다음 주간 미팅 일정 없음 — 준비 노트 안 만듦").
5. **쓰기** (순서 = 노트 → 6 의 hq 반영 → 회의록 한 번 → 자료):
   1. 노트가 없으면 `prepareMeeting` (1번의 대상 · 자리) — 반환 `meetingId` = 미팅 폴더 id.
   2. 6 의 hq 반영 (태스크 키가 필요하다).
   3. **회의록 = `writeMeetingMinutes`** — 쓰기 직전 `getMeeting` 으로 다시 읽어 (미팅 중에 웹 · 다른 사람이 넣은 안건이 있을 수 있다) 2번의 내용을 그 위에 합치고, 6 의 키를 채워 (자리표시 없이) `{ meetingId, content, baseModifiedTime: minutes.modifiedTime }` 으로 **한 번** 쓴다 (`content` 는 § 준비 5 와 같은 모양 · `stale` 도 같다).
   4. 자료 — Google Drive 커넥터 `create_file { parentId: <meetingId>, title, base64Content, contentMimeType, disableConversionToGoogleType: true }` (안 그러면 Google 문서로 바뀐다). 첨부 바이트를 넘길 수 없으면 "자료는 Drive 앱 · hq 파일 화면에서 이 폴더로 올려 주세요" 로 폴더 링크를 준다.
6. **후속 태스크**: 확인받은 항목마다 `createTask` (사외 미팅이면 `customer` = 그 미팅의 회사 이름 — `listMeetings` 의 `company` 그대로 · `description` = § 규칙 「공통 (글)」 의 설명 쓰는 법대로 — 첫 줄에 어느 미팅의 어느 안건 (번호만 말고 제목까지) 에서 나온 일인지와 무슨 일인지, 그 아래 할 일 · 회의에서 정한 조건을 `- ` 항목으로) → `linkResource { taskId, kind: "meeting", ref: <미팅 폴더 id>, title: "<YYYY-MM-DD> <주제 (공백)>" }` → 만든 키를 회의록 "후속 태스크" 절 (사내 = 그 안건 · 기타 블록 액션 표의 키 칸 · 링크 `[HQ-0000](https://hq.nodemill.ai/tasks?task=HQ-0000)`) 에 채운다.
   - 사내 갱신: `getTaskByKey` (id) → `changeTaskStatus` · 마감 · 담당이 바뀌었으면 `updateTask` → 이 미팅에도 `linkResource` (같은 형식).
   - 사내 종료: `getTaskByKey` → `changeTaskStatus { taskId, status: "done" }` → `addComment { taskId, body }` (`body` = 「공통 (글)」 의 댓글 쓰는 법대로 — 어느 미팅에서 닫기로 했는지 · 왜 (회의록의 결정 · 논의) · 그래서 이 태스크가 어떻게 되는지. 예 `11-04 주간 미팅에서 이 태스크는 닫기로 했어요. ○○금속 단가표는 따로 만들지 않고, ○○금속이 보내 준 표를 그대로 쓰기로 했거든요. 그래서 이 태스크로 더 할 일은 없어요.`) → 이 미팅에도 `linkResource` (미팅 화면에서 종료가 보이게).
   - 사내 이월: `### 진행 중 · 예정` 에서 언급 없이 미완료로 남은 키도 전부 (마감으로 들어온 연결 밖 행 포함) 이 미팅에 `linkResource` — 안 그러면 다음 주 준비에서 빠진다.
   - 사내 마감 미정: `dueDate` 없이 `duePending: true` 로 만든다 (담당의 홈 「내 할 일 › 날짜 미정」 · 브리핑 「날짜 미정」 에 뜬다).
   - 사내 "각자 · 모두": 참석자마다 1개 (`<할 일> — <이름>`) · 전부 이 미팅에 `linkResource`.
   - 담당이 정해지지 않은 행은 만들지 않는다 (키 칸 `(담당 정해지면)`).
7. **다음 주간 미팅 노트** (사내 주간 미팅만 · 4번에서 승인받았으니 다시 묻지 않는다): 5 · 6 이 끝난 뒤
   - 일정 = `listEvents { from: 내일, to: 오늘+8 }` 의 제목 `주간 미팅` 첫 것 → `prepareMeeting { eventId }`. 없으면 만들지 않는다 ("일정부터 잡을까요" 도 묻지 않는다 — 8번 보고에 한 줄). `UNAVAILABLE` 이면 `prepareMeeting { date: 이번 미팅 + 7일, meetingTitle: "주간 미팅" }` (그 날짜가 이미 지났으면 만들지 않는다).
   - 지난 미팅 = § 준비 3 의 검색 대신 **방금 정리한 이 미팅** (`getMeeting { meetingId: <이 폴더 id> }` — 당일 정리한 미팅은 `to: 전날` 에 안 잡힌다). 두 절 = § 준비 4 (이 미팅이 직전 미팅 · 진행 중 · 예정의 마감 한도 = 다음 미팅 날짜 + 6일 · doing · review 는 마감과 무관 · 완료는 보통 `없음` — 기준 줄로 시점이 보인다) · 「태스크가 없는 지난 액션」 = § 준비 4 대로 이 회의록의 모든 안건 · 기타 액션 표에서 (그 블록에 남은 행 · 이번에 새로 생긴 `(담당 정해지면)` 행 모두) · 그 회의록의 `## 다음 미팅으로 넘김` = ` (넘어옴)` 안건 → § 준비 5 대로 `writeMeetingMinutes`.
   - 그 노트가 이미 있었으면 (`created: false` — 누가 미리 안건을 넣은 것) 안건 행 · 블록은 그대로 두고, 넘어온 안건 · 「태스크가 없는 지난 액션」 블록 (빠진 행) 만 덧붙이고 (이미 있으면 다시 넣지 않는다) `## 지난 액션` 절을 이 미팅 기준으로 바꾼다.
8. **확인 · 보고**: `getMeeting { meetingId }` 로 회의록 (`minutes.status: ok` · `status: 완료`) · 자료가 보이는지 확인 → 미팅 제목 · 자리 · hq 링크 (`hqUrl`) · 만든 태스크 키를 보고. 7번을 했으면 다음 노트의 날짜 · hq 링크 · 넘어간 안건 수 · 진행 중 · 예정 수 · "안건은 hq 미팅 화면이나 '안건 추가해 — …' 로 미리 넣으세요 · 미팅 날 '주간 미팅 준비' 하면 그 주에 끝낸 일이 완료 표에 들어가요" 를 더하고, 안 만들었으면 "다음 주간 미팅 일정이 캘린더에 없어 준비 노트를 만들지 않았어요" 한 줄.

## 찾기 · 회상 — "지난 가나 미팅 뭐였지" · "ERP 시연 때 뭐 정했지"

1. `listMeetings` — 회사면 `company`, 주제 · 내용이면 `q` (제목 부분 일치 + 회의록 · 자료 내용의 낱말 일치), 기간이면 `from` / `to`. `contentSearched: false` 면 내용 검색이 안 된 것 — 다른 낱말로 한 번 더.
2. 고른 미팅을 `getMeeting` → 결정 사항 · 후속 태스크 (`tasks` 의 키 · 상태) 를 요약하고 `hqUrl` 링크.
3. 주간 미팅이면 지난 몇 주 회의록의 `### 진행 중 · 예정` (묶음 표 여럿 — 키로 찾는다 · 그 전 회의록은 `## 지난 액션` 표 · 옛 구조 "1. 지난 액션 확인") 에서 같은 키가 연속으로 미완료인 것을 한 줄로 ("HQ-0123 3주째 doing"). "그 주에 뭐 끝냈지" 는 `### 완료` 절.
4. 회의록이 없는 미팅 (`minutes: null`) 은 자료 이름 · 링크를 준다. `minutes.status: unreadable` 이면 Drive 에서 열라고 안내.

## 자료 덧붙이기 — "이 슬라이드 어제 가나 미팅에 넣어"

1. `listMeetings { company, from }` 로 미팅을 찾는다 (여럿이면 고르게 한다).
2. 파일 이름 · 미팅을 한 줄로 확인 → 커넥터 `create_file` 로 그 미팅 폴더 (`id`) 에 업로드 (`disableConversionToGoogleType: true`).
3. 회의록이 있으면 "자료" 절에 파일 이름을 더할지 묻는다 → `getMeeting` → `minutes.content` 에 합쳐서 `writeMeetingMinutes` (§ 준비 5 와 같은 모양).

## 규칙

- `회의록.md` 는 hq 도구로만 쓴다 — 커넥터로 `회의록.md` 를 새로 만들거나 이름을 바꾸지 않는다 (같은 노트에 웹이 안건을 넣는다). 고칠 때는 항상 `getMeeting` 으로 지금 내용을 읽고 합쳐서 `writeMeetingMinutes` (`baseModifiedTime`) — `stale` 이면 다시 읽어 합쳐 다시 · 다른 사람이 쓴 내용을 덮어쓰지 않는다.
- 위키 양식의 칸별 설명 (HTML 주석) 을 노트에 옮기지 않는다 · 미팅을 위키 문서로 쓰지 않는다 — 미팅 = 공유 드라이브 (이 스킬). 노트의 `## 안건` · `## 기타` (사외 `## 안건` · `## 논의` · `## 결정 사항`) 제목 줄 이름을 바꾸지 않는다 (hq 가 안건을 덧붙이는 표지).
