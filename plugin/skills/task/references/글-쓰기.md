# hq 에 쓰는 글 — 기준 · 전 · 후 예

> 본문 `SKILL.md` § 글 쓰기 의 풀이. 같은 기준 문장이 `meeting` · `briefing` 스킬에도 있다. 이 레포는 공개라 예는 지어낸 것 (○○ = 가린 이름) 이고, 예 2 만 hq 플러그인 자체의 실제 글이다.

## 기준

hq 에 쓰는 글 (설명, 댓글, 확인 요청, 답) 은 처음 읽는 사람이 회의록이나 대화 없이 그 글만 읽고 이해하게 풀어 쓴다. 해요체 문장으로 쓰고 명사로 끝내지 않는다. 어디서 나온 일인지, 왜 하는지, 지금 상태, 무엇을 하면 끝인지, 언제까지인지 (안 정했으면 그렇다고), 다음에 누가 무엇을 하는지 (남은 일이 없으면 없다고) 를 넣는다. 기호 (`·` `→` `=` `/` `—`) 로 낱말을 이어 붙이지 않고 말로 잇는다 (늘어놓을 때는 쉼표나 `와`, `과`). 처음 읽는 사람이 모를 수 있는 번호, 키, 파일, 화면, 도구 이름, 내부 용어는 무엇인지, 어디인지 함께 쓴다. 일에 대한 사실 (날짜, 금액, 이름, 결정, 이유) 은 원문에 있는 것만 쓴다. 길이는 필요한 만큼 쓴다.

읽는 사람 = 그 회의 · 대화에 없었던 동료. 끊어 쓴 요약을 받으면 빠진 말을 짐작으로 메우다 틀리거나, 무슨 뜻인지 몰라 다시 묻는다.

## 하나씩

| 규칙 | 하지 않는다 | 한다 |
|---|---|---|
| 해요체 문장 | `검토 완료` · `전달 필요` · `반영 예정` | `검토했어요` · `전달해 주세요` · `금요일에 반영할게요` |
| 맥락 | `기타 1 · 대표 피드백` | `11-04 주간 미팅에서 대표님이 …라고 해서 잡은 일이에요` |
| 기호로 잇지 않기 | `견적서로 대체 → 종료` · `룰 = 위키 …` · `상세 · 논의 · 결정 블록` | `견적서로 대신하기로 해서 닫아요` · `규칙은 위키 「…」 에 정리했어요` · `상세, 논의, 결정 블록` |
| 번호 · 키 · 파일 · 도구 | `안건 3` · `제14조 ④` · `HQ-0042` · `커넥터` 만 | `안건 3 (단가표)` · `계약서 제14조 ④ (적용 법인)` · `HQ-0042 (견적서 보내기)` · `Google Drive 커넥터` |
| 지어내지 않기 | 원문에 없는 이유 · 날짜 · 금액 · 다음 계획을 덧붙임 | 모르면 `정하지 않았어요` · 날짜 · 금액 · 이름은 원문 그대로 |

- 설명 모양: 첫 문단에 무엇을, 왜, 언제까지. 그 아래에 세부 (받을 것, 조건, 결정할 것) 를 줄마다 완결된 문장 목록으로. 진행하며 생긴 이야기는 설명에 쌓지 않고 댓글로.
- 태스크 제목 · 회의록 표 · 위키는 이 기준의 대상이 아니다 (짧은 이름 · 양식이 정해진 글).

## 예 1 — 미팅에서 나온 할 일의 설명 (지어낸 예)

전:
```
마감 미정 — 언급 없음
2026-11-04 주간 미팅 (안건 3). ○○금속 단가표 = 기존 엑셀 양식 · 품목 코드 열 추가 · 확인 후 전달.
```

후:
```
11-04 주간 미팅 안건 3 (○○금속 단가표) 에서 나온 일이에요. ○○금속에 보낼 단가표는 지금 쓰는 엑셀 양식을 그대로 쓰고, 품목 코드 열만 하나 더 넣기로 했어요. 마감은 회의에서 날짜로 정하지 않았어요. 담당이 정해요.
- 품목 코드 열을 넣은 단가표를 만들어요.
- 품목 코드가 맞는지 확인한 뒤 ○○금속에 보내요.
```

## 예 2 — 끝낸 일의 설명 (hq 플러그인 자체의 실제 글)

전:
```
사내 회의록 「지난 액션」 을 hq 의 태스크 → 에픽 → 로드맵 연결로 묶었다 (제목으로 짐작하지 않음).
- 모양: 완료 · 진행 중 · 예정 아래 #### 로드맵 (로드맵 이름 링크 · 에픽 칸) · #### 에픽 (로드맵 없는 에픽) · #### Tasks (에픽 없는 태스크) · 완료만 건수 · 묶음 없으면 소제목 생략 · 순서 = 계획 시작 순
- 바꾼 곳: 플러그인 미팅 스킬 (0.28.0) · 위키 회의록 양식 · 사내 미팅 · 플러그인 설치 문서 (버전 숫자 제거) · hq 테스트 양식 사본 · 사용법 1줄
```

후:
```
주간 미팅 회의록의 「지난 액션」 을 로드맵과 에픽 단위로 묶어 보이게 바꿨어요. 어느 묶음에 넣을지는 태스크 제목으로 짐작하지 않고, hq 에서 태스크에 실제로 연결된 에픽과 로드맵을 따라가요.
- 완료 표와 진행 중 표가 각각 로드맵별, 로드맵 없는 에픽별, 에픽 없는 태스크로 나뉘어요. 묶을 것이 없으면 그 소제목은 빼고, 순서는 계획 시작이 이른 것부터예요.
- 바꾼 곳은 플러그인 미팅 스킬 (0.28.0), 위키의 회의록 양식과 사내 미팅 문서, 플러그인 설치 문서 (버전 숫자를 뺐어요), hq 테스트의 양식 사본과 사용법 한 줄이에요.
```

## 예 3 — 이 정도면 되는 댓글 (지어낸 예)

```
11-11 주간 미팅에서 ○○ 견적서 이야기가 나왔어요. 유지보수 기간은 1년으로 하고, 첫 달 유지보수비는 받지 않기로 했어요. 이 기준으로 견적서를 다시 정리해서 올려 주세요. 기간을 다르게 하자는 의견이 있으면 댓글로 남겨 주세요.
```
어디서 나온 이야기인지, 무엇이 정해졌는지, 받는 사람이 무엇을 하면 되는지가 문장으로 다 있다.

## 예 4 — 요지만 준 "댓글 달아 줘" (지어낸 예)

태스크 `HQ-0042 — ○○ 연동 담당자 연락처 · 가능 여부 확인` · 사용자: `HQ-0042 에 담당자 연락처 받았고 다음 주 화요일에 통화하기로 했어 — 댓글 달아`
→ 바로 달지 않고 보인다: `HQ-0042 에 이렇게 달까요? — "○○ 연동 담당자 연락처를 받았어요. 다음 주 화요일에 통화해서 연동이 가능한지 확인할게요."` → 좋다고 하면 `addComment`.
- `○○ 연동` · `가능한지 확인` 은 태스크 제목에서 온 말이다. 사용자가 말하지 않은 날짜 · 결과 · 이유는 넣지 않는다.
- 사용자가 따옴표로 문장을 줬으면 (`HQ-0042 에 "연락처 받았어요" 라고 달아`) 묻지 않고 그 문장 그대로 단다.
