# 미팅

원본 = 회사 Google **공유 드라이브**. 미팅 1건 = 폴더 1개 · 안의 **`회의록.md`** 하나가 미팅 전 = 안건 노트 (`status: 준비`) · 정리 뒤 = 회의록 (`status: 완료`). **`회의록.md` 쓰기는 전부 hq 도구** — `prepareMeeting` (노트 준비: 있으면 그대로 · 없으면 자리 폴더 + 양식 뼈대를 만든다) · `addMeetingAgenda` (안건 1개 덧붙이기 — 노트가 없으면 만들고 넣는다) · `writeMeetingMinutes` (본문 전체 쓰기 — 지난 액션 · 넘어온 안건 채우기 · 정리). hq 미팅 화면 (`https://hq.nodemill.ai/meetings`) 의 "안건 추가" 와 같은 함수라 웹 · Claude 가 같은 노트에 쌓는다. **자료 파일 (슬라이드 · pdf · 이미지) 올리기만 Google Drive 커넥터** (사용자 본인 권한).

## 갈래 — 요청에 맞는 파일을 먼저 읽는다

## 사내 · 사외

- **사외 (고객사 미팅) = 실제로 외부 고객과 만난 미팅만** → `고객사/<회사>/미팅/`. 참석자에 고객사 사람이 있으면 사외.
- **고객 일에 대해 우리끼리 한 미팅은 사내** → `운영/미팅/` 아래 (그 고객 일의 주제 폴더). 주제가 고객 일이어도 고객사 폴더에 두지 않는다 — 고객과의 미팅과 헷갈린다.

## 양식 · 쓰는 규칙

- **양식 원본 = 위키 `_templates/회의록-사내.md` · `_templates/회의록-사외.md`** — hq 가 새 노트에 자동으로 쓴다. 모양을 봐야 할 때 (노트 없이 정리할 때 · 블록을 손으로 쓸 때) `getWikiPage { path: "_templates/회의록-사내.md" }` 로 읽는다. 양식의 HTML 주석 (칸별 설명) · `{{…}}` 자리표시 · `{{번호}}` 견본 줄은 노트에 넣지 않는다 — 뼈대만.
- 사내 노트를 쓰는 규칙 (구분선 · 머리 3줄 · 안건 표 · 앵커 · 이름 · 링크 · 준비 / 정리 뒤 칸) = `references/사내-회의록.md`. CLOVA 요약 → 논의 · 결정 · 액션 = `references/clova-변환.md`.
- 녹음 = CLOVA Note (오프라인 · 온라인 모두 폰 앱 — 온라인은 노트북 스피커 소리). 정리 입력 = CLOVA **요약** 텍스트 붙여넣기 · 다운로드 파일.

## 찾기 · 회상 — "지난 가나 미팅 뭐였지" · "ERP 시연 때 뭐 정했지"

1. `listMeetings` — 회사면 `company`, 주제 · 내용이면 `q` (제목 부분 일치 + 회의록 · 자료 내용의 낱말 일치), 기간이면 `from` / `to`. `contentSearched: false` 면 내용 검색이 안 된 것 — 다른 낱말로 한 번 더.
2. 고른 미팅을 `getMeeting` → 결정 사항 · 후속 태스크 (`tasks` 의 키 · 상태) 를 요약하고 `hqUrl` 링크.
3. 주간 미팅이면 지난 몇 주 회의록의 `### 진행 중 · 예정` (묶음 표 여럿 — 키로 찾는다 · 그 전 회의록은 `## 지난 액션` 표 · 옛 구조 "1. 지난 액션 확인") 에서 같은 키가 연속으로 미완료인 것을 한 줄로 ("HQ-0123 3주째 doing"). "그 주에 뭐 끝냈지" 는 `### 완료` 절.
4. 회의록이 없는 미팅 (`minutes: null`) 은 자료 이름 · 링크를 준다. `minutes.status: unreadable` 이면 Drive 에서 열라고 안내.

## 자료 덧붙이기 — "이 슬라이드 어제 가나 미팅에 넣어"

1. `listMeetings { company, from }` 로 미팅을 찾는다 (여럿이면 고르게 한다).
2. 파일 이름 · 미팅을 한 줄로 확인 → 커넥터 `create_file` 로 그 미팅 폴더 (`id`) 에 업로드 (`disableConversionToGoogleType: true`).
3. 회의록이 있으면 "자료" 절에 파일 이름을 더할지 묻는다 → `getMeeting` → `minutes.content` 에 합쳐서 `writeMeetingMinutes` (`references/준비.md` 5 와 같은 모양).

## 규칙

- `회의록.md` 는 hq 도구로만 쓴다 — 커넥터로 `회의록.md` 를 새로 만들거나 이름을 바꾸지 않는다 (같은 노트에 웹이 안건을 넣는다). 고칠 때는 항상 `getMeeting` 으로 지금 내용을 읽고 합쳐서 `writeMeetingMinutes` (`baseModifiedTime`) — `stale` 이면 다시 읽어 합쳐 다시 · 다른 사람이 쓴 내용을 덮어쓰지 않는다.
- 위키 양식의 칸별 설명 (HTML 주석) 을 노트에 옮기지 않는다 · 미팅을 위키 문서로 쓰지 않는다 — 미팅 = 공유 드라이브 (이 스킬). 노트의 `## 안건` · `## 기타` (사외 `## 안건` · `## 논의` · `## 결정 사항`) 제목 줄 이름을 바꾸지 않는다 (hq 가 안건을 덧붙이는 표지).
- hq 쓰기 오류 (INVALID `details.reason`): `all-day` = "세부 일정 (시각) 을 먼저 정해 주세요" (`schedule` 스킬로 시각을 넣을지 묻는다 · 이미 노트가 있는 종일 일정은 덧붙여진다) · `done` = "이미 정리된 미팅이에요" · `ended` = 끝난 일정 (지난 미팅은 정리 흐름) · `busy` · `untitled` = 가려지거나 제목 없는 일정 · `unknown-link` · `unknown-member` = 그 자료 · 기안을 고쳐 다시 · `unreadable` · `too-large` · `layout` · `template` = 쓰지 말고 "Drive 에서 직접 고쳐 주세요" (양식이면 위키 `_templates/` 를 고치도록) 안내 후 멈춤 · `no-minutes` = `prepareMeeting` 먼저.
- 미팅 위치 밖 폴더 · 이름이 날짜로 시작하지 않는 폴더 · 묶음 4단보다 깊은 폴더 id 는 hq 에서 `NOT_FOUND` — `references/자리-규칙.md` 대로 옮기자고 (또는 폴더 이름을 `YYYY-MM-DD_주제` 로) 안내한다 (이동은 사용자가 Drive 앱에서 — 다시 만들고 지우는 우회는 폴더 id 가 바뀌어 태스크 연결이 끊기므로 하지 않는다).
- 비밀번호 · 키 · 개인정보가 든 메모는 올리기 전에 한 번 확인한다. CLOVA Note 는 연동 API 가 없다 — 녹음 · 요약은 사용자가 CLOVA 에서 하고 텍스트를 준다 (영상 파일은 CLOVA 에 못 올린다 — 음성 m4a · mp3 · aac · amr · wav).
- 공통 (글): hq 태스크 설명 · 댓글을 쓰는 법 = `references/글-쓰기.md` (후속 태스크 설명 · 종료 댓글을 쓰기 전에 읽는다).
- 공통: id 는 조회로만 얻는다 · `UNAVAILABLE` = Drive · 위키 · 캘린더 한도 · 장애 (잠시 뒤 다시 · 재시도를 반복하지 않는다) · 401 · 연결 오류 = "hq 다시 로그인 (Code `/mcp` · claude.ai 플러그인 Connectors 탭)" 안내 후 멈춤 · 결과 JSON 을 붙이지 않는다.
