## 준비 — "주간 미팅 준비해 줘" · "<주제> 미팅 준비해 줘"

1. **대상**: `references/안건-추가.md` 1 과 같다.
2. `prepareMeeting { eventId | meetingId | date + meetingTitle }` → 노트 (있으면 그대로 · 없으면 만든다 — `place-required` 면 `references/자리-규칙.md` 대로).
3. **직전 미팅**: 주간 = `listMeetings { kind: "internal", q: "주간 미팅", to: 이 미팅 전날 }` 에서 `group` 이 `주간-미팅` 인 첫 행 (옛 `YYYY/MM/` 자리의 주간 미팅은 `group` 이 없고 `topic` 이 `주간-미팅` · `주간 미팅`) · 주제 미팅 = `listMeetings { kind: "internal", to: 이 미팅 전날 }` 에서 `group` 이 같은 주제인 첫 행 → `getMeeting`. **직전 미팅 시작** = 그 회의록 `**일시**` 줄의 시작 시각 (한국 시간 · 시각이 없으면 그날 0시). 연 · 월 자리 (`group` 없음) 미팅 · 사외 미팅은 지난 액션을 채우지 않는다 (사내 연월 = 두 표 모두 `없음` 1행).
4. **채울 내용** (모양 · 묶음 · 순서 · 칸 = `references/사내-회의록.md` § 지난 액션) — `## 지난 액션` 은 두 절 · **hq 태스크만** (보류함으로 옮긴 · 지운 태스크는 조회 목록에 안 나온다 → 뺀다 · 다시 찾지 않는다):
   - **조회** (주간 — 한 번씩 부르고 그 결과로 고른다 · 묶음은 제목으로 짐작하지 않는다): `listTasks { completedFrom: <직전 미팅 날짜> }` (완료) · `listTasks { status: "todo" }` · `{ status: "doing" }` · `{ status: "review" }` (안 끝난 일 전부 — 에픽 · 담당 · 마감 · `duePending` · 상태가 함께 온다) · `listEpics { activeOnly: false }` · `listRoadmaps { activeOnly: false }` (에픽 → 로드맵 · 이름 · 계획 시작) · `listMembers` (담당 이름). 주제 미팅은 직전 미팅 `tasks` 키마다 `getTaskByKey` + `listEpics { activeOnly: false }` · `listRoadmaps { activeOnly: false }` · `listMembers` (주제 미팅은 몇 주씩 떨어져 목록이 커진다).
   - `### 완료` = **직전 미팅 시작 이후 끝낸 태스크** (`completedAt` 은 UTC — 한국 시간 = +9시간으로 비교). 주간 = 완료 목록에서 `completedAt` 이 직전 미팅 시작 이후인 것 전부 (구성원 전원 · 미팅 연결과 무관) · 주제 = 직전 미팅 `tasks` 중 `done` 인 키. **뺄 키**: 직전 회의록에 이미 done 으로 적힌 것 (그 회의록의 완료 표 행 · 진행 중 표 상태 `done` · 옛 회의록의 `## 지난 액션` 한 표 상태 `done` · 액션 표 구분 `종료 → done` · `(done)`) · 이 노트의 진행 중에 남는 것 (아래). 행 = 제목 (주간 미팅에서 직전 미팅 `tasks` 에 있던 키면 끝에 ` (지난 액션)`) · 담당 (`assigneeId` → `listMembers` 이름) · 완료일 (`completedAt` 의 한국 시간 날짜) · 키 링크. 맨 위 줄 `지난 미팅 (YYYY-MM-DD HH:MM) 이후 완료 N건 · YYYY-MM-DD HH:MM 기준` (기준 = 지금).
   - `### 진행 중 · 예정` = **안 끝난 태스크** — 주간 = 직전 미팅 `tasks` 중 done 이 아닌 것 + 연결과 무관하게 마감 (`dueDate`) 이 **이 미팅 날짜 + 6일 이하** (이미 지난 마감 포함 — 다음 주까지 끝낼 일) 인 것 + 연결 · 마감과 무관하게 상태가 `doing` · `review` 인 것 (지금 손대고 있는 일) (`duePending` 인 todo 는 연결된 것만) · 주제 = 직전 미팅 `tasks` 중 done 이 아닌 것. 담당 · 마감 · 상태 = 조회한 hq 값 (회의록 글자를 옮기지 않는다). 정리 6번이 이 절의 미완료 키를 매주 이 미팅에 연결해 이어 간다. 다시 부를 때 피드백이 적힌 행은 끝났어도 상태 `done` 으로 이 절에 남긴다 (값은 완료 목록의 같은 키).
   - **태스크가 없는 지난 액션** (직전 회의록 안건 · 기타 블록 액션 표에서 키 칸에 태스크 키 `HQ-…` 가 없는 행 — 할 일 칸이 빈 행 · `액션 없음 — …` 은 뺀다) = `## 기타` 의 `### 기타 1. 태스크가 없는 지난 액션` 블록 (`references/사내-회의록.md`) — 없으면 만들지 않는다.
   - 첫 미팅이면 두 절 모두 `없음 (첫 미팅)` 1행.
   - 넘어온 안건 = 직전 회의록 `## 다음 미팅으로 넘김` (옛 구조 "6.") 항목마다 안건 표 1행 + 블록 1개 (번호 = 마지막 + 1) — 제목 끝 ` (넘어옴)` · 기안 = 지난 블록의 기안 (없으면 `—`) · 상세 첫 불릿 = `지난 미팅 [YYYY-MM-DD 주제](<hqUrl>) 에서 넘어옴 — <이유>`. 이미 있는 안건이면 다시 넣지 않는다.
5. **쓰기**: `getMeeting { meetingId }` (이 미팅) 의 `minutes.content` (회의록.md 원문 그대로 · frontmatter 포함) 위에 4 를 합친다 — 다른 안건 · 내용 · frontmatter 는 한 글자도 바꾸지 않는다 → `writeMeetingMinutes { meetingId, content, baseModifiedTime: minutes.modifiedTime }` (`content` = 그 원문을 고친 것 — frontmatter 를 따로 다시 조립하지 않는다). **`stale` 이면 `getMeeting` 으로 다시 읽어 새 내용 위에 같은 변경을 다시 합쳐 다시 쓴다** (덮어쓰지 않는다 · 두 번째도 `stale` 이면 멈추고 알린다). **다시 부르면** (이미 채운 노트) `## 지난 액션` 절 (제목부터 다음 `---` 앞까지 — 절 안에는 `---` 가 없다) 만 4 로 새로 쓴다 — 진행 중 · 예정에 누가 쓴 피드백은 키로 찾아 (어느 묶음 표에 있든) 새로 쓴 그 행에 옮기고, 안건 · 다른 절은 그대로 (넘어온 안건 · 「태스크가 없는 지난 액션」 블록은 빠진 것만 넣고 이미 있는 것은 다시 넣지 않는다). `status: 완료` (정리된) 노트는 다시 채우지 않는다 — "이미 정리된 미팅이에요".
