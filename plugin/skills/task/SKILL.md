# hq 태스크 작성

자연어 → `createTask`. **id 는 추측하지 않는다** — 반드시 조회 도구로 얻는다.

## 절차

1. 사용자 말에서 뽑는다: 제목 · 사일로 (업무 영역) · 담당자 · 프로젝트 (있으면) · 시작일 · 마감일 · 설명 · 체크리스트.
2. id 를 찾는다 (필요한 것만, 각 1회):
   - 사일로 → `listSilos` (법인 운영 · ERP · HQ · 홈페이지). "ERP 쪽", "홈페이지 건" 같은 표현을 여기에 맞춘다.
   - 담당자 → `listMembers` (`activeOnly: true`). "대표" = role `ceo`, "CTO" = `cto`, 그 외는 이름으로. 담당자를 말하지 않았으면 **로그인한 구성원 (나)** 로 하되 보고에 명시한다.
   - 프로젝트 → 사용자가 프로젝트를 언급했을 때만 `listProjects` 로 기존 것을 찾는다. 없으면 만들지 말고 "프로젝트 '~' 가 없다 — 새로 만들까요?" 라고 묻는다.
3. 날짜는 `YYYY-MM-DD` (한국 시간). "다음 금요일" · "이번 주 안에" 같은 상대 표현은 오늘 날짜 기준으로 계산해 **확인 문장에 실제 날짜를 적는다**.
4. **애매하면 묻는다** — 사일로를 알 수 없거나, 담당자가 둘 이상에 맞거나, 기간 표현이 두 가지로 읽히면 만들기 전에 한 번에 묻는다 (질문은 하나로 모아서).
5. `createTask` 호출: `title` · `siloId` · `assigneeId` 필수, `projectId` · `startDate` · `dueDate` · `description` · `checklist` 는 있을 때만.
6. 보고: `HQ-0001 — 제목` 형식으로 키 · 제목 · 사일로 · 담당 · 마감을 한 줄씩. 결과 JSON 은 붙이지 않는다.

## 예

"ERP 사일로에 '인터뷰 패키지 발송' 태스크, 담당 대표, 마감 다음 금요일"
→ `listSilos` (ERP) · `listMembers` (ceo) → `createTask { title: "인터뷰 패키지 발송", siloId, assigneeId, dueDate: "2026-11-06" }` → "HQ-0042 — 인터뷰 패키지 발송 / ERP / 대표 / 마감 2026-11-06"

## 규칙

- 같은 요청으로 태스크를 두 번 만들지 않는다. 호출이 실패했는지 모르면 `search` 로 제목을 먼저 찾는다.
- 삭제 · 종료 같은 되돌리기 어려운 도구 (`deleteTask` · `closeProject`) 는 이 스킬에서 쓰지 않는다.
- 401 · 연결 오류면 "hq 연결이 끊겼다 — Claude Code 는 `/mcp` 에서, claude.ai 는 플러그인 Connectors 탭에서 hq 에 다시 로그인" 을 안내하고 멈춘다.
