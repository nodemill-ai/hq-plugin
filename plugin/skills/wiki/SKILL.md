# hq 위키

위키 원본 = 비공개 GitHub 레포의 Markdown (Obsidian 호환). 쓰기는 hq 가 대신 커밋한다 (`writeWikiPage` — 커밋 메시지에 내 이름이 남는다). 읽기는 hq 웹 (`hqUrl`) 또는 여기서.

**회사 계정 · 비밀번호는 위키 · 드라이브 · hq 에 없다** — Bitwarden 조직 금고 (`https://vault.bitwarden.com` · hq 사이드바 · 더보기의 "계정") 에서 찾으라고 한 줄로 안내한다. 위키 · 드라이브를 뒤지지 않는다.

## 작성 규칙

위키는 **참조용**이다 — 나중에 "이거 뭐였지 · 어떻게 하지 · 왜 이렇게 됐지" 를 찾을 때 읽는다. 무슨 일을 했는지 검토하는 작업 보고가 아니다.

- **사실 · 결정 · 절차 · 위치만** 쓴다. 논의 과정 · 선택 이유 나열 · 배경 설명 · 발언 요약은 쓰지 않는다 (필요하면 hq 태스크 · 결정 기록 링크 하나).
- 한 항목 = 한 줄. 문서 하나는 화면 한 장 안.
- 템플릿 (`_templates/` — 회의록 = 결정 · 후속 태스크 · 보류 / 결정-기록 = 결정 한 문장 · 범위 · 버린 선택지 · 근거 3줄 이하 · 되돌릴 조건 / 운영-가이드 = 언제 · 절차 · 주의 · 관련) 의 **칸만** 채운다. 빈 칸은 지우고, 칸을 늘리지 않는다. 템플릿 맨 위 HTML 주석이 그 문서의 규칙이다 — 본문에 복사하지 않는다.
- **올리기 전 자체 검사**: 대화 내용을 요약해 넣은 문장 · "~했고 ~였다" 식 서술 · 4줄 이상의 근거가 보이면 지운다.
- 비밀번호 · 키 값은 쓰지 않는다 — "Bitwarden 의 ~" 처럼 위치만.

## 쓰기 — "위키에 올려"

1. **완성본 확인**: 올릴 내용 (대화에서 만든 회의록 · 결정 · 가이드 등) 이 정해졌는지 본다. 초안 단계면 먼저 § 작성 규칙대로 줄이고 "이대로 올릴까요?" 로 확인받는다.
2. **지도**: `listWikiTree` 1회 → `entries` (폴더 · 문서) · `templates` (`_templates/*.md`).
3. **자리 고르기**: 내용에 맞는 기존 폴더를 고른다 (예 고객사 미팅 → `고객사/<회사>/`). 같은 주제 문서가 이미 있으면 새로 만들지 말고 **수정** 흐름으로 간다.
   - **맞는 폴더가 없으면 새 폴더를 제안하고 승인받는다** — "`고객사/광일금속/` 폴더를 새로 만들어 넣을까요?" 처럼 경로 1개를 제안 (최상위 폴더도 마찬가지). 승인 없이 새 폴더를 만들지 않는다.
   - 파일 이름: 날짜가 있는 기록은 `YYYY-MM-DD-주제.md`, 그 외는 `주제.md` (공백 대신 `-`). 경로는 `.md` 로 끝나야 하고 `_templates/` · `assets/` 안에는 못 쓴다.
4. **템플릿 적용**: 종류가 맞는 템플릿 (회의록 · 결정-기록 · 운영-가이드 등, `templates` 목록) 을 `getWikiPage` 로 읽어 그 **목차 구조를 따르고** frontmatter 를 채운다:
   ```
   ---
   title: <제목>
   date: <YYYY-MM-DD, 한국 시간 오늘 또는 그 일의 날짜>
   author: <로그인한 구성원 이름 — 모르면 listMembers 로 찾지 말고 사용자에게 묻는다>
   tags: [<종류>, <관련 고객사 · 제품 등 1~3개>]
   ---
   ```
   맞는 템플릿이 없으면 frontmatter + `# 제목` 으로 시작하는 자유 형식 (§ 작성 규칙은 그대로).
5. **올리기**: 경로 · 제목을 한 줄로 확인받은 뒤 `writeWikiPage { path, body, message }` (message = 커밋 한 줄, 예 "광일금속 10/31 미팅 회의록 추가"). 새 파일이면 `baseSha` 없이.
6. **보고**: 제목 · 경로 · `hqUrl` 링크. 결과 JSON 은 붙이지 않는다.

## 수정 — "위키 고쳐", "~ 에 추가해"

1. 문서를 찾는다 (아래 읽기 1~2) → `getWikiPage` 로 현재 원문 (`content`) 과 `sha`.
2. 원문에 변경을 합친 **전체 본문** 을 만든다 (frontmatter 유지 · 필요하면 `date` 는 그대로, 내용만 고침). 바뀌는 부분을 사용자에게 요약해 확인받는다.
3. `writeWikiPage { path, body, message, baseSha: sha }`.
4. `INVALID` + "current sha" 가 오면 그 사이 누가 고친 것이다 → `getWikiPage` 로 **다시 읽고** 새 원문에 변경을 다시 합쳐 **1회만** 재시도한다. 또 실패하면 멈추고 사용자에게 알린다.

## 삭제 — "위키 지워", "이 문서 삭제"

1. 사용자가 **명시적으로** 지우라고 했을 때만. 문서를 찾는다 (아래 읽기 1~2) → `getWikiPage` 로 `path` · 제목 · `sha`.
2. 지울 문서의 경로 · 제목을 보여 주고 "이 문서를 지울까요? (되살리기는 GitHub 이력에서만)" 로 **확인받는다**. 여러 개면 하나씩 목록으로 확인.
3. `deleteWikiPage { path, baseSha: sha }` — `baseSha` 는 **필수**: 먼저 `getWikiPage` 로 읽고 그 `sha` 를 넣는다 (확인받은 그 버전만 지운다). 메시지는 생략하면 "<경로> 삭제" — 이유가 있으면 `message` 한 줄.
4. `INVALID` + "current sha" = 그사이 누가 고쳤다 → 다시 읽어 바뀐 내용을 보여 주고 다시 확인받는다 (자동 재시도 안 함). 루트 `README.md` · `_templates/` · `assets/` 는 지울 수 없다 — 그대로 안내.
5. 이 문서를 링크한 태스크가 있으면 (웹 문서 화면 아래 "참조 태스크") 링크가 끊긴다고 한 줄 알린다. 이동 · 이름 변경 = 새 경로에 `writeWikiPage` → 옛 문서 `deleteWikiPage` (둘 다 확인 뒤).

## 읽기 — "위키에서 ~ 찾아봐"

1. `listWikiTree` → 경로 · 파일명에서 후보를 고른다 (검색은 파일 이름 기준 — 본문 검색은 아직 없다).
2. 후보가 여럿이면 경로 목록을 보여 주고 고르게 한다. 하나면 `getWikiPage` 로 읽는다.
3. 답 = 필요한 부분 요약 + `hqUrl` 링크. 읽은 내용은 이어지는 작업 (태스크 만들기 · 답장 초안 등) 에 그대로 쓴다.
4. 못 찾으면 "위키에 '~' 문서가 없다" 고 말하고, 새로 만들지 묻는다.

## 태스크와 연결

"이 문서를 HQ-0042 에 붙여" → `getTaskByKey` 로 taskId → `linkResource { taskId, kind: "wiki", ref: <path>, title: <문서 제목> }`.

## 규칙

- 이동 · 이름 변경 전용 도구는 없다 — 위 삭제 5번 (새로 쓰고 옛 문서 삭제). 지운 문서를 되살리려면 위키 레포 git 이력에서 (관리자).
- `_templates/` 는 읽기만 (템플릿을 바꾸려면 레포 커밋).
- 본문에 비밀번호 · 키 · 개인 연락처를 넣지 않는다. 보이면 빼자고 먼저 말한다.
- 1MB 를 넘는 본문은 거부된다 — 나눠서 여러 문서로.
- `UNAVAILABLE` 이면 GitHub 한도 · 장애다 — 잠시 뒤 다시 하자고 안내하고 재시도를 반복하지 않는다.
- 401 · 연결 오류면 "hq 연결이 끊겼다 — Claude Code 는 `/mcp` 에서, claude.ai 는 플러그인 Connectors 탭에서 hq 에 다시 로그인" 을 안내하고 멈춘다.
